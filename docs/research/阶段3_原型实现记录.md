# 阶段 3：EvoAudit-MR 原型实现记录

> 加固状态（2026-08-12）：已完成独立 hidden oracle、同分布 heldout、patch-feature routing、真实字段访问观测、分离证书/日志和对应测试。17 项自动测试全部通过；加固版端到端 demo 已在独立临时输出目录验证成功。工作区内原 `artifacts/prototype-seed-0/` 是 v1 历史产物，不用于后续 Pilot 指标。

## 已完成的最小闭环

实现路径：[evoaudit_mr/](evoaudit_mr/)。原型以可重放的 AliasTool 环境实现以下完整链条：

`可见失败轨迹 → Trace2PatchStub / PatchCatalogue → typed tool-adapter patch → contract-checked router → target/replay/safety probes → paired execution → commit/reject → certificate 与 hidden full audit`。

实现不调用 LLM、外部 API 或真实工具；底座 agent 是确定性最小 harness。这样阶段 3 验证的是 update-admission 逻辑，不会将候选生成质量或模型采样方差混入结论。

## 实际运行结果

运行命令（在 `evoaudit_mr` 目录）：

```powershell
$env:PYTHONPATH = "$PWD\src"
python -m evoaudit_mr.runners.prototype_demo --manifest configs/prototype_manifest.json
python -m unittest discover -s tests -v
```

实际输出：

| Patch | Hidden full audit | Fixed heldout | EvoAudit-MR | EvoAudit-MR 决定原因 |
| --- | --- | --- | --- | --- |
| `semantic_adapter` | reliable | commit | commit | — |
| `positional_adapter` | unreliable | commit | reject | `target_mr_failed` |
| `alias_only_adapter` | unreliable | commit | reject | `replay_regression` |
| `restricted_lookup_adapter` | unreliable | commit | reject | `safety_invariant_failed` |

加固后，Direct 与 fixed heldout 在这个受控的四候选 demo 中提交 4 条、错误提交 3 条；公平化的 fixed random audit 使用相同三桶和相同预算，能拦截安全违规候选，提交 3 条、错误提交 2 条；EvoAudit-MR 提交 1 条可靠 patch，错误提交为 0。此结果只用于原型验收，不能作为论文主实验结果。

- [x] fixed heldout 通过、EvoAudit-MR 正确拒绝、hidden audit 支持判断的可读案例；
