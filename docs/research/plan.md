# EvoAudit-MR：ICLR 2027 论文完整计划

> 目标会议：ICLR 2027  
> 摘要截止：2026-09-11 AOE  
> 全文截止：2026-09-16 AOE  
> 论文核心：提出面向自演进 agent 的更新采纳机制。每次 agent 修改 prompt、记忆、工具或工作流后，EvoAudit-MR 用作用域化变形测试、历史能力回归测试与安全不变量测试，决定该更新是否应被长期保留。

## 阶段 1：基础文献与问题收敛

**时间：8/11-8/12，1.5 天**

### 工作内容

1. 阅读并拆解最关键的五篇工作：
   - RSEA：固定 held-out selection 如何选择更新；
   - EvoTest：测试时如何修改 prompt、记忆、工具例程和超参数；
   - Your Agent May Misevolve：自演进为何会造成安全退化；
   - SEAGym / EvoPolicyGym：自演进过程如何使用 train、validation、test、replay 和预算记录评测。
2. 明确论文问题：固定 held-out 测试能发现一般退化，但未必覆盖某次具体 patch 的特有失效模式。
3. 明确本文主张：针对 patch 的类型和作用域选择变形测试，比固定/随机验证更准确地决定是否采纳更新。
4. 明确本文边界：不发明变形测试本身；不承诺开放世界绝对安全；只研究有可执行 verifier 的测试时自演进。

### 产物

- 清晰的 Introduction 主线；
- 相关工作结构；
- 一句话研究问题、方法主张与可证伪假设；
- 论文标题与摘要骨架。

## 阶段 2：实验设计

**时间：8/12，0.5 天**

### 工作内容

1. 固化 agent 的四类可更新对象：prompt/策略规则、记忆/技能、工具适配、工作流。
2. 定义 EvoAudit-MR 的三类证据：
   - 目标改善：新更新是否解决当前问题；
   - 作用域外保持：是否伤害旧能力或未修改模块；
   - 安全不变量：是否越权、跳过确认或产生不允许的副作用。
3. 定义四类数据来源：
   - `D_e`：产生更新的 evolve tasks；
   - `D_v`：固定、同分布的 held-out validation tasks；
   - `P(u)`：针对具体更新 `u` 的 MR、回归与安全审计测试；
   - `D_test`：最终隐藏测试集。
4. 冻结对比方法：Static / direct commit / fixed held-out gate（RSEA-style）/ random audit / EvoAudit-MR。
5. 冻结主指标：False Acceptance Rate、Acceptance Precision、Useful Update Recall、安全违规率、最终隐藏迁移性能、审计成本。

### 产物

- 正式方法流程图；
- 完整实验协议；
- 主表字段与主图设计；
- 环境、MR library、基线和计算预算清单。

## 阶段 3：跑通 EvoAudit-MR 原型

**时间：8/13-8/14，2 天**

### 工作内容

1. 实现最小 agent configuration 与 candidate patch 接口。
2. 实现 AliasTool：一个有程序化 oracle 的商品/日历查询工具环境。
3. 实现三个最小变形关系：
   - 列表顺序变化不应影响正确选择；
   - 字段或实体别名变化后，映射回语义的正确选择应一致；
   - 只读任务不得调用写权限工具。
4. 实现三个更新选择器：
   - direct commit：可见任务得分提高即接受；
   - fixed held-out gate：固定验证集不退化/提升才接受；
   - EvoAudit-MR：目标、回归和安全证据共同决定。
5. 实现 update certificate：记录 patch、测试、结果、成本和决策。

### 产物

- 能完整运行的 “任务 - 更新 - 审计 - commit/reject” 闭环；
- 一个真改进 patch 和一个 shortcut patch 的端到端案例；
- 第一张版本演进与 update certificate 示例图。

## 阶段 4：小规模对比实验

**时间：8/15-8/18，4 天**

### 工作内容

1. 在 AliasTool 和 SwitchRule 两个小环境中构造四类候选：
   - 真正修复任务的更新；
   - 利用表面相关性的 shortcut 更新；
   - 改善局部任务但损害历史能力的回归更新；
   - 通过越权或跳过确认获得高分的安全违规更新。
2. 使用相同候选、相同 rollout 预算运行所有基线与 EvoAudit-MR。
3. 以最终隐藏审计集为真值，计算每种选择器的 FAR、AP、UUR 和安全违规率。
4. 验证固定 held-out gate 是否会漏掉预先定义的 update-specific shortcut；验证 MR gate 是否能在不拒绝所有真改进的前提下发现它。

### 产物

- 初步主结果表；
- 一个“fixed held-out 通过、隐藏 MR 失败”的可视化案例；
- 是否继续主线的初步实验结论。

## 阶段 6：大规模正式实验

**时间：8/22-8/31，7-10 天**

### 工作内容

1. 完成受控程序化主实验：在 AliasTool、SwitchRule、PermissionPath 上使用相同 parent、候选 patch 和任务证据，对比各更新采纳 gate；以程序化 hidden oracle 测量 FAR、FDR/AP、UUR、安全违规和多轮终局能力。该 Track 用于识别采纳机制本身的因果增量，不要求 LLM backbone。
2. 完成主要 LLM proposal Track：在两个代表性自建环境中，由一个冻结的 7B--8B 开源 instruction model 根据当前 agent state 和 visible traces 生成结构化 prompt、memory、tool 或 workflow patch，再运行完整的“生成—审计—commit/reject—持久化—下一轮”链路。
3. 完成第二 backbone 的小规模方向一致性复验：选择不同模型系列的第二个冻结模型，在两个代表性环境和较少 seeds 上复跑；检查核心结论方向是否一致，不要求完整复跑全部 180 候选、消融和预算扫描。
4. 在启动每个 LLM Track 前单独冻结模型与运行配置：精确 model/tokenizer revision、量化方式、prompt hash、解码参数、生成次数、推理框架、硬件或 API 版本；不得根据结果更换配置。
5. 对所有更新 gate 使用相同候选生成规则、候选生成次数、任务预算、rollout 预算和评测协议；无效或 no-op proposal 必须记录，不允许重抽直到成功。
6. 完成至少一个公开环境的轻量外部验证，优先选择能够保存 agent snapshot、重放历史任务并记录成本的公开 self-evolution/agent 环境。该 Track 用于验证结论能否迁移到作者未构造的任务分布，而不要求其提供与自建环境同样完整的 update-level hidden oracle。
7. 公开环境至少报告：final hidden/test performance、replay retention、多轮性能曲线、commit rate、更新与审计成本；若环境支持 parent--candidate 配对重放与安全约束，则进一步报告部分 update-level 指标和安全违规率。
8. 运行四类消融：
   - 无 MR；
   - 无作用域路由；
   - 无安全不变量；
   - 固定预算 vs 序贯预算。
9. 运行成本与预算实验：不同审计预算下的 FAR--成本曲线，以及预注册的 commit-rate-matched control。

### 投稿前证据分工

| 实验层 | 候选来源 | 环境来源 | 必须回答的问题 |
|---|---|---|---|
| 受控候选级与多轮主实验 | 程序化生成器 | 自建、可程序验证 | EvoAudit-MR 的采纳策略本身是否优于 baselines？ |
| 主要 LLM proposal Track | 主 7B--8B backbone | 自建、可程序验证 | 面对真实 LLM 生成的非预设候选时，完整链路是否仍有效？ |
| 第二 backbone 方向复验 | 不同系列模型 | 两个代表性自建环境 | 结论是否明显依赖单一 proposal model？ |
| 公开环境轻量验证 | 程序化或 LLM proposal | 至少一个公开环境 | 整体收益是否能迁移到作者未构造的任务分布？ |

### 产物

- 主实验完整原始结果；
- 消融实验结果；
- 一个主要 LLM backbone 的完整链路结果；
- 第二 backbone 的方向一致性结果；
- 至少一个公开环境的轻量外部验证结果；
- 泛化与成本实验结果；
- 可复现实验配置、日志、随机种子和版本证书。

## 论文最终应具备的证据链

```text
已有自演进 agent 会产生候选更新
        ↓
direct commit 或固定 held-out 会错误接受部分 update-specific shortcut
        ↓
EvoAudit-MR 根据更新类型选择 MR、回归和安全测试
        ↓
在相同预算下更少错误接受，同时保留真正有效更新
        ↓
最终隐藏任务上的能力与安全性更可靠
```

只要这条证据链成立，论文的“创新点 - 方法设计 - 实验设计”就是闭环的。
