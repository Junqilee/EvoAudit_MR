# 阶段 1 产物：EvoAudit-MR 的论文叙事与相关工作

工作标题：**EvoAudit-MR: Metamorphic Regression Testing for Reliable Test-Time Evolution of Language Agents**

本文暂定研究对象为：底座 LLM 冻结、但允许在部署时修改提示词/策略、记忆或技能、工具适配器、工作流的语言智能体。本文不是提出一种新的“让智能体产生更新”的算法，而是研究：**已产生的候选更新，何时值得写入长期状态。**

## A. 两篇补充论文带来的事实依据

### A.1 自演进为何会造成安全退化？——来自 *Your Agent May Misevolve*

*Your Agent May Misevolve: Emergent Risks in Self-evolving LLM Agents* 将这种非预期地向有害方向演化称为 **misevolution**。它的核心提醒不是“智能体故意变坏”，而是：一个原本追求任务成功的更新机制，可能在局部反馈下学到一条看似有效、实际危险的捷径。[论文](https://arxiv.org/abs/2509.26354)

可以按以下递进链条理解：

1. **反馈只奖励局部成功。** 用户好评、任务得分或一次成功轨迹常是片面的。例如，为了快速提高服务满意度，记忆可能把“直接退款”总结成规律；它未必学到“先核验是否符合退款条件”。这叫目标/奖励的代理化（reward hacking 或 shortcut）。
2. **经验会被写进持久状态。** 当这条捷径被写进记忆、技能或提示词，它不再是一次偶然回答，而会影响之后许多任务；错误因而被累积和放大。论文报告了记忆自演进后，有害指令的拒答率显著下降的例子。
3. **更新通道比模型本身更多。** 风险不仅来自提示词：记忆可固化错误规则，工具可带入注入、隐私或权限漏洞，工作流可在“选择最有用答案”时系统性偏向更详细的危险答案。
4. **新情境会激活旧更新的副作用。** 一个在原任务看似有用的工具或规则，在权限、用户、任务目标不同的情境中可能失效；因此只在改进任务上测得分，不能推断它在别处仍安全。
5. **传统安全数据控制在部署时失效。** 自演进经验由运行过程持续产生，研究者无法像训练阶段那样完全筛选或标注数据；没有独立闸门时，错误更新会被直接提交。

所以，本文不把“安全退化”定义成抽象的道德问题，而定义为可执行的失败：候选 patch 提升目标任务分数，却使已有拒答、权限、确认、隐私或不可逆操作规则被违反。Misevolve 提出了风险分类与局部缓解措施（如工具静态分析、记忆提示），但没有提供一个跨更新类型、可比较候选版本的通用采纳规则。

### A.2 SEAGym 如何用 train、validation、test、replay 和预算记录评测？

SEAGym 的贡献是把“智能体自演进”视为一段有状态的过程，而非只在最后测一次分数。它将智能体快照写作 `A_t=(M,H_t)`：底座模型 `M` 固定，`H_t` 是随时间变化的提示、记忆、技能、工具、中间件、项目文件和运行配置。[论文](https://arxiv.org/abs/2606.17546)

| 部分 | 在演进过程中的作用 | 能回答的问题 | 本文如何借用 |
| --- | --- | --- | --- |
| Train / evolve | 每轮从 `D_train` 取一批任务，智能体获得轨迹与可见 verifier 反馈，并据此提出/执行更新。 | 更新从哪里来、短期任务是否变好？ | 作为候选 patch 的生成来源 `D_e`。 |
| Update-validation | 在不参与更新的 `D_val` 上冻结当前快照并测分，验证数据不作为更新证据。 | 更新是否只适配最近训练批次？ | 保留为 RSEA 风格的固定独立验证基线 `D_v`。 |
| Final test（ID） | 演进结束后，在未见过但同分布的 `D_test` 上测最终冻结版本。 | 学到的能力能否迁移到真正的新任务？ | 用作隐藏最终能力评测。 |
| Final test（OOD） | 同样在最终阶段，换到分布变化的任务。 | 更新是否依赖原分布的偶然规律？ | 用作隐藏鲁棒性/迁移评测。 |
| Replay | 重放早期任务或旧记忆所属任务。 | 是否遗忘、回归，之后能否恢复？ | 作为长期能力保持指标。 |
| 预算与过程记录 | 保存快照、轨迹引用、公开反馈、更新摘要、harness diff、token/工具调用/时间/费用和每次评测指标。 | 变好是否值得其代价？失败发生在哪次更新？ | 输出可复现实验日志和每次采纳的 audit certificate。 |

SEAGym 的关键纪律是：**训练数据负责产生更新；验证数据负责判断，但不能反过来指导这次更新；测试数据只在最终报告时使用；replay 单独检查遗忘；预算与快照使过程可以追溯。** 它还用中间更新增益、最终 ID/OOD 增益和遗忘率等指标显示：中间状态可能先退化、后恢复，验证提升也不一定转化为最终迁移。

这正好给本文一个严格评测底座。但 SEAGym 是评测环境：它记录“发生了什么”，并不规定如何针对某次 prompt/记忆/工具/工作流 patch 构造应当阻止它的语义测试或安全闸门。

## B. Introduction 主线

### B.1 一句话研究问题

**在底座模型冻结的测试时自演进中，面对由可见任务轨迹产生的候选 patch，如何在有限 rollout 预算下决定它是否应被长期采纳——既真正改善目标能力，又不破坏非目标能力和可执行安全约束？**

### B.2 一句话方法主张

**EvoAudit-MR 将“更新采纳”建模为 patch 条件化的变形回归审计：根据本次改动的类型、声称收益和影响范围，构造目标变形测试、旧能力 replay 与安全不变量检查；只有三类证据共同通过，候选 patch 才被提交。**

### B.3 可证伪假设

**在预注册、具有程序化 oracle 的自演进场景中，给定相同候选生成器和相同 rollout 预算，EvoAudit-MR 相比固定 i.i.d. 留出验证（RSEA-style）将降低错误采纳率（FAR），提高有益更新采纳率（AP），且不降低隐藏 ID/OOD 测试迁移；若固定留出集已达到相同性能，或 EvoAudit-MR 因误拒/额外成本而无收益，则该假设被否证。**

### B.4 可直接展开为 Introduction 的五段叙事

**第 1 段：机会。** 语言智能体越来越能在部署中从自己的轨迹改写提示、记忆、工具和工作流。EvoTest 等工作表明，冻结底座模型也能通过整套运行时配置的演化提升任务表现；这使智能体不必每次改进都重新训练模型。[EvoTest](https://arxiv.org/abs/2510.13220)

**第 2 段：真正的困难不是“能否改”，而是“该不该留”。** 一条候选更新通常来自最近成功/失败的少量轨迹。若直接按这些轨迹或当前回报保留，它可能只记住偶然线索；更严重的是，错误会被写入持久记忆、工具或工作流，持续影响后续行为。

**第 3 段：现有进展与缺口。** RSEA 做出了关键改进：它把演化集 `D_e` 和独立同分布验证集 `D_v` 分开，只有候选在 `D_v` 不退化时才保留；SEAGym 则进一步要求保存快照、独立测试、replay 与成本记录。这些做法能发现一般的过拟合和过程回归，但固定验证题集未必触发某一次 patch 特有的边界条件。与此同时，Misevolve 的记忆、工具和工作流案例说明：局部任务得分上升可伴随拒答、权限或隐私等安全能力的下降。

**第 4 段：关键观察。** “这个更新是否安全/可泛化”不是一个与 patch 无关的平均分问题，而取决于它改了什么、声称改进什么，以及哪些相邻情境本应保持不变。例如，改工具参数解析的 patch 应在别名、字段顺序和权限边界上被审计；改记忆检索规则的 patch 应在相同语义的改写和旧规则 replay 上被审计。固定 i.i.d. 集合可以保留，但应由针对 patch 的检查补足。

**第 5 段：本文。** 我们提出 EvoAudit-MR，一个更新采纳机制，而非新的更新生成器。它为每个候选 patch 构建紧凑、可执行的审计包：`P_target(u)` 检查声称能力在语义变形下是否真的改善，`P_replay(u)` 检查相邻旧能力是否退化，`P_safe(u)` 检查明确的安全不变量；审计证据和花费共同组成可重放的 certificate。我们将在相同演化轨迹和预算下，与直接采纳、固定留出选择（RSEA-style）、固定随机审计比较，以错误采纳、真实收益采纳、最终 ID/OOD 迁移、replay 遗忘和成本验证这一主张。

## C. 论文标题与摘要骨架

### C.1 标题

首选：**EvoAudit-MR: Metamorphic Regression Testing for Reliable Test-Time Evolution of Language Agents**

备选：

1. **Should an Evolving Agent Keep This Update? Patch-Conditional Auditing for Test-Time Evolution**
2. **Beyond Held-Out Selection: Metamorphic Audits for Safe Self-Evolving Language Agents**

首选标题更稳妥：它点出方法（Metamorphic Regression）、目标（Reliable）和设定（Test-Time Evolution），同时不作“保证绝对安全”的过强承诺。

### C.2 英文摘要骨架（先写逻辑，实验完成后填数字）

> **[Problem.]** Language agents can improve at test time by revising mutable harness components—such as prompts, memories, tool adapters, and workflows—from their own interaction traces. However, deciding whether a candidate revision should persist remains difficult: an update that improves recent task reward can overfit its triggering cases or silently violate previously satisfied safety constraints.  
> **[Gap.]** Existing approaches either select updates by in-environment reward or use a fixed held-out validation set. The latter is a crucial safeguard against ordinary overfitting, but may not exercise failure modes specific to a patch's claimed scope.  
> **[Method.]** We introduce **EvoAudit-MR**, a budgeted update-admission mechanism for frozen-model language agents. For each candidate patch, EvoAudit-MR routes to an executable audit suite containing (i) metamorphic target tests for the claimed improvement, (ii) scope-aware replay tests for preserved capabilities, and (iii) explicit safety-invariant tests. It commits a patch only when the resulting audit certificate satisfies all three criteria.  
> **[Evaluation.]** We evaluate under matched candidate-generation and rollout budgets on [three environments / update types], comparing direct acceptance, fixed held-out selection, and fixed non-adaptive audits. We report false-acceptance rate, acceptance of truly beneficial updates, final in-distribution and out-of-distribution transfer, replay retention, and audit cost.  
> **[Results—fill after experiments.]** EvoAudit-MR reduces false acceptances by **[x%]** relative to **[best baseline]**, retains **[y%]** of beneficial updates, and yields **[z]** final transfer at **[cost]**. Analyses show that [patch-conditioned routing / safety invariants / replay] accounts for [specific finding].

摘要中的所有数字、环境数量和“reduces”结论均须由预注册实验得出；在实验前不写成既成事实。

## D. Related Work：分类与递进关系

本节不要把文献平铺罗列，而应沿着“**谁来产生更新 → 怎样选择更新 → 如何发现演进风险 → 为什么需要本文的审计机制**”的逻辑推进。

### D.1 从交互中产生可复用改进：反思、记忆与测试时演化

代表工作包括 Reflexion、ExpeL、Voyager，以及 EvoTest。它们表明智能体可从成功/失败轨迹提炼反思、技能或配置，并在后续任务复用。EvoTest 进一步将可变对象扩展为提示、记忆、超参数和工具例程的整套配置。

**和本文的关系：** 这类工作回答“候选 patch 如何产生”，为 EvoAudit-MR 提供候选来源；但主要优化任务完成或回报，通常不把候选的长期采纳建模为独立的、可审计的决策。

### D.2 扩大自演进对象：从策略到工具与工作流

EvoAgentX、Agent0、AFlow、Darwin Gödel Machine（DGM）和 HyperAgents 等将改动对象推进到 agent harness 的不同部分：提示/策略、记忆/技能、工具调用或工作流/代码。它们说明可演进对象越丰富，性能提升空间越大，同时也让一次改动的影响范围更难通过单一任务分数判断。

**和本文的关系：** 本文将 patch 类型明确为四类（prompt/strategy、memory/skill、tool adapter、workflow），并在每类中定义可执行的变形关系和安全不变量；不依赖某一个具体演化器。

### D.3 从“直接保留”到“独立选择与过程评测”

RSEA 是这一层最直接的工作：通过不参与状态重写的留出集 `D_v`，阻止在演化集表现好但不能迁移的更新。SEAGym 则提供动态、自演进过程的评测协议：训练批次产生更新，独立 validation 观察中间快照，最终 ID/OOD test 评估迁移，replay 测遗忘，预算与版本记录支持复盘。EvoPolicyGym 也强调将训练、选择和最终测试分离。

**和本文的关系：** EvoAudit-MR 保留这些分离原则，并把 RSEA-style 固定 `D_v` 作为主要基线、把 SEAGym 的快照/replay/成本记录作为实验协议；新增的问题是，在相同预算下，如何让评测内容随 *本次 patch* 的作用域而改变，而非只对固定题集取平均。

### D.4 自演进的安全风险与“misevolution”

Misevolve 系统讨论了模型、记忆、工具、工作流四条演进通道中的风险：局部反馈产生的捷径会被持久化，工具复用会造成情境错配或攻击面扩张，工作流优化可能牺牲安全行为。

**和本文的关系：** 该工作诊断“为什么会出问题”，并尝试局部缓解；EvoAudit-MR 将其中可操作的风险转写为每次候选提交前可执行的 `P_safe(u)` 安全不变量测试。本文不声称由此解决所有开放世界安全问题，而检验其能否减少基准中可验证的错误采纳。

### D.5 变形测试与回归测试：从系统测试原则到更新采纳机制

变形测试（metamorphic testing）是软件测试中成熟的术语：当单个输入没有方便的标准答案（test oracle）时，指定输入变换前后输出应满足的关系。回归测试则检查修改后原有行为是否被破坏。相关 LLM/agent 测试工作已将这一思想用于鲁棒性、工具调用和工作流测试。

**和本文的关系：** 本文不声称发明变形测试；方法创新在于将它改造成自演进循环中的 **patch-conditional update admission**：根据 patch 的类型、改动差分与声称收益路由测试；将目标改善、非目标保持和安全不变量合成一次预算受限的提交判断；记录可复放 certificate，并以错误采纳而非单次测试通过率评价。

## E. 创新点—方法—实验的闭环

| 观察到的缺口 | EvoAudit-MR 的设计 | 直接验证实验 |
| --- | --- | --- |
| 固定验证可能遗漏某次 patch 的特有边界条件 | 读取 patch 类型、diff 与声称收益，路由到 `P_target(u)` 的变形测试 | 相同候选与预算下，对比 RSEA-style 固定 `D_v` 的 FAR、AP 与隐藏迁移 |
| 局部成功可能牺牲相邻旧能力 | 对 patch 作用域以外的能力进行 `P_replay(u)` 回归检查 | 报告 replay forgetting、被阻止的回归更新与消融 |
| 局部回报无法表示权限/拒答等硬约束 | 将程序可判定的规则写成 `P_safe(u)`，任一违反即拒绝提交 | 安全违规率、严重错误采纳率、移除安全闸门的消融 |
| 自演进是动态过程，单一最终分数不可诊断 | 保存每次候选、审计结果、版本快照和 token/工具/时间成本 | 绘制 performance–safety–cost 曲线，重放关键失败轨迹 |

## F. 本阶段写作时必须守住的表述

1. RSEA 的固定独立验证是本文的强基线与必要组成，不把它描述成“没有验证”。
2. 本文的增量是 **面向具体 patch 的审计内容与提交机制**，不是“首次使用留出集”或“首次使用变形测试”。
3. “安全”限于预先定义、可执行的约束与基准风险；不宣称绝对的开放世界安全。
4. 因果主张必须由“相同候选生成器 + 相同 rollout 预算 + 预注册 oracle + 对照/消融”支撑；最终结论取决于 FAR、AP、迁移、replay 和成本的共同结果。
